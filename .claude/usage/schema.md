# Local Usage Tracker — Event Schema

Append-only JSON-lines event log for **local development workflow** usage. Records are written to a private live file outside the git worktree and published to a per-developer team file inside the repo (see "File location" below and the README for the two-zone model).

**Scope:** development workflow assets only (`.claude/commands/`, `.claude/rules/`, `.claude/hooks/`, `.claude/agents/`, `.claude/CLAUDE.md`, `AGENTS.md` bridge). Not deployed runtime telemetry — see FP-192 for scope boundary.

## Event fields

| Field | Type | Required | Description |
|---|---|---|---|
| `timestamp` | string (ISO-8601 with timezone) | yes | When the event was recorded. |
| `repo` | string | yes | Repository identifier. Derived from `git remote get-url origin` (last `owner/repo` segment, no `.git`). Enables cross-repo aggregation. |
| `developer` | string | yes | Author identity. Derived from `git config user.email`. Per-developer filter in the dashboard. |
| `platform` | enum | yes | Tool that produced the event: `claude-code` \| `codex` \| `other`. Set via env var `USAGE_PLATFORM` per tool. Defaults to `other` if unset. |
| `command` | string | yes | Workflow name. For slash commands, the full string incl. leading slash (e.g. `/jira-plan`). For direct asset use, the asset's stable name. |
| `asset_path` | string | yes | Repo-relative path to the asset (e.g. `.claude/commands/jira-plan.md`). |
| `asset_type` | enum | yes | `command` \| `rule` \| `hook` \| `agent` \| `bridge` \| `other`. |
| `trigger` | enum | yes | How the workflow was invoked: `slash-command` \| `bridge` \| `manual` \| `hook` \| `direct`. |
| `outcome` | enum | yes | Lifecycle state: `started` \| `completed` \| `partial` \| `blocked` \| `failed` \| `skipped`. |
| `note` | string | no | Free-text friction / value / changed-intent note from the developer. |
| `candidate_action` | enum | no | Reviewer's suggested next step: `keep` \| `improve` \| `demote` \| `retire` \| `generalize`. |

## Lifecycle conventions

- **`started`** — workflow invocation detected (e.g. user typed `/jira-plan`). Written automatically by the Claude Code `UserPromptSubmit` hook or the Codex bridge-side call.
- **`completed` / `partial` / `blocked` / `failed` / `skipped`** — terminal outcome written by the workflow doc itself at end-of-run via `scripts/record_usage.py --outcome <state>`. **All five are terminal**, including `partial` — it means "the workflow finished but with open follow-ups", not "still in progress". The dashboard treats any of these five as closing a `started` event.

A `started` event with no matching terminal event within 24h is treated as **abandoned** by the dashboard and surfaced in a dedicated panel + KPI. Abandoned starts are a process gap (the workflow doc's mandatory end-of-run recorder call wasn't executed) — they are not a normal terminal state and should not be left to accumulate.

## Asset-type mapping

| Asset path prefix | `asset_type` |
|---|---|
| `.claude/commands/` | `command` |
| `.claude/rules/` | `rule` |
| `.claude/hooks/` | `hook` |
| `.claude/agents/` | `agent` |
| `.claude/CLAUDE.md`, `.claude/ONBOARDING.md`, `AGENTS.md` | `bridge` |
| anything else | `other` |

## Example event

```json
{"timestamp":"2026-05-24T20:55:14+08:00","repo":"leonyap27/Funding_paper_agent","developer":"leonyap.work@gmail.com","platform":"claude-code","command":"/jira-plan","asset_path":".claude/commands/jira-plan.md","asset_type":"command","trigger":"slash-command","outcome":"completed","note":null,"candidate_action":null}
```

## File location (FP-196 two-zone model)

- `~/.claude-usage/<owner>/<repo>/events.jsonl` — **private live JSONL** outside the git worktree. Written by `scripts/record_usage.py` on every event. Branch-independent by construction (git cannot touch it).
- `.claude/usage/team/events-<hash>.jsonl` — **per-developer team profile** inside the repo. One file per developer; the file name uses a 10-char SHA-1 of `git config user.email`. Written only by `scripts/publish_usage.py`, and only ever for the current developer's own file.
- `.claude/usage/inventory.json` — seeded asset inventory (regenerated by `scripts/seed_inventory.py`).
- `.claude/usage/viewer/index.html` — HTML dashboard. Served by `scripts/open_dashboard.py`, which exposes `/_usage/team-events.jsonl` and `/_usage/live-events.jsonl`.

Legacy paths `.claude/usage/events.jsonl` and `.claude/usage/events/` are gitignored — anything that lands there is migration residue.

## Cross-repo aggregation

Each event carries its own `repo` field. Concatenate `team/events-*.jsonl` files from sibling repos and load them in the dashboard. The live zone is keyed by `<owner>/<repo>` so cross-repo data never collides.

## Privacy / PII

`developer` is the developer's git email, which is already public in commit history. No other PII is captured. Do not put secrets in `note` — the team file is committed.
